# 72 - Frontend Knowledge Growth and Feedback Correction Protocol

2026-10-06. Registered before implementation evaluation. All files, package caches and temporary data stay on D:. Existing Node/Python installations on C: may be read and executed.

Teach six immutable HTML/CSS nodes with curated facts, example query prototypes and parameterized executable examples. Freeze them; record hashes, pinned answers and old automatic retrieval decisions. Then append four React nodes without modifying old records. Recheck original data, pinned answers, and held-out old queries. Growth does not train neural weights; this is a small retrieval-and-template skill prototype, not general coding ability or human biology.

Routing uses fixed hashing features and cosine similarity to immutable query prototypes, with novelty and ambiguity thresholds selected using development queries only. No global vocabulary or IDF is refit when adding nodes. Benchmark known-question retrieval, unknown-topic handling, clarification, React novelty before learning, and React retrieval after learning. Test/development wording is disjoint. Freeze all lessons, correction candidates, thresholds and executable checks before opening the held-out query/execution set. Report coverage and abstentions, not just accuracy on accepted answers.

Run real HTML/CSS DOM and React interaction checks using local Node, jsdom, React and ReactDOM on D:. jsdom cannot validate visual layout or browser accessibility behavior fully. Examples are manually authored reusable templates with varied parameters, not generated arbitrary code. Test direct node execution and automatically routed execution separately.

Inject one counter bug deliberately: directly changing a state variable without using its setter. The failure is artificial and must be reported that way. Feedback supplies a corrected functional state update and an official React source. Reject unverified feedback and corrections failing development execution checks. Append a verified correction node linked to its predecessor; latest verified view selects the correction, while pinned original versions remain retrievable. This is externally guided, test-gated correction, not autonomous invention of a repair or proof of semantic truth.

Use held-out parameters and phrases only after decisions are frozen. Rerun every old HTML/CSS question and executable task after React and its correction. Test restart persistence, duplicate-ID refusal, bad-feedback refusal, missing provenance, file-damage recovery and invalid-backup refusal in isolated copies. Preserve earlier growth experiments unchanged.

Record results, failures, corrections, dependencies, sources and scope limits in the Obsidian vault. New notes 73 and 74 will contain detailed and latest results.
